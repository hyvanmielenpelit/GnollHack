# Game Data Files

## Critical Rules
- **Never edit `.lev` files directly**. Edit `.des` files and compile them with `levcomp`.
- **Never edit `nhdat` directly**. It is an archive generated by `dlb`.
- **Never edit `dat/dlb.lst` directly**. It is generated by `afterdlb.proj` from the `<DlbList>` item group in `win/win32/vs/files.props` on every build, and is gitignored. Edit `files.props` instead.
- **Never edit `dat/dungeon.pdf` directly**. It is generated from `dat/dungeon.def` by `makedefs -e`. Edit `dungeon.def`.

## Data Pipeline
1. Edit source files in `dat/` (e.g., `*.des`, `dungeon.def`, `data.base`).
2. Run `makedefs` for text databases (e.g., `makedefs -d` for `data.base`, `-r` for rumors, `-h` for oracles) and `makedefs -e` to turn `dungeon.def` into `dungeon.pdf`.
3. Run `levcomp` to compile `.des` into `.lev` (e.g., `levcomp.exe castle.des medusa.des ...` in `dat/`).
4. Run `dgncomp` to compile `dungeon.pdf` into `dungeon` (e.g., `dgncomp.exe dungeon.pdf` in `dat/`).
5. Run `dlb` to package everything into `nhdat` (e.g., `dlb.exe cIf dat/dlb.lst bin/$(Configuration)/$(Platform)/nhdat`). The file list comes from `<DlbList>` in `files.props`; `dat/dlb.lst` is generated from it immediately beforehand.

> **Note:** When building via Visual Studio (`GnollHack.sln`), these steps run automatically via MSBuild targets. See the `build_pipeline` skill for the full flag reference table and automation details.

### Two pipelines — Windows and mobile

> ⚠️ **The pipeline above builds the Windows `nhdat` only.** Android and iOS
> get their `nhdat` from a second, parallel toolchain that runs inside WSL
> (`makedefsdroid`, `levcompdroid`, `dgncompdroid`, `dlbdroid`). The two do
> **not** share a file list: the Windows one comes from `<DlbList>` in
> `files.props`, while the mobile one is **hardcoded in the
> `RemotePostBuildEvent` command in `dlbdroid.vcxproj`**.
>
> **When you add a data file that must ship in `nhdat`, update both lists.**
> Updating only `files.props` produces a Windows build where the file works
> and Android/iOS builds where it is silently missing. See the
> `build_pipeline` skill, section *Two Data Pipelines*.

## Level Files (`.des`)
- Syntax defines dungeon layouts, rooms, corridors, monsters, and objects.
- Uses a custom scripting language parsed by `levcomp`.
- `MAZE` syntax defines strict grid layouts.
- `ROOM` syntax defines procedurally generated rooms.

## Text Databases
- `data.base`: Monster and object descriptions.
- `rumors.tru` / `rumors.fal`: Fortune cookie text.
- `oracles.txt`: Oracle responses.
- `engrave.txt`: Random engravings found on the floor.
