# GnollHack replay_breaking_todo_list.txt
# GnollHack may be freely redistributed.  See license for details.

Register of interface changes deliberately deferred because they would change
the GUI interop contract or the replay recording format, or might break
compatibility with replays recorded by earlier versions. They are collected
here so that they can be made together in a release where such a break is
acceptable, instead of each being worked around separately.

Each entry has an ID (RB-nnnn, never reused), a target version, a status
(Open, In progress, Done in <version>, or Dropped), the current state and its
workaround, the intended change, the files involved, what it could break, and
how to verify it. When an entry is done, keep it and set its status.

==============================================
RB-0001  Mirror menu_item in the select_menu interop and the window ports

Target:   4.3.1 or later
Status:   Done 2026-11-26, in the first release after commit f63aa17f2
          (recorded 2026-11-26 the same day; it turned out not to break
          replays, so it was not deferred)

Before
  menu_item (include/wintype.h) gained a third field, itemflags (uint64_t,
  MENU_ITEMFLAGS_*), for the per-row stash mark of the Pick up, Pick & Stash
  and Take out menus. ClientCallback_SelectMenu (GHGame.cs) returned two int64
  values per selected row, [identifier, count], so the mark rode inside the
  count: -3 / -3-n meant "the opposite of the menu's stash default", decoded by
  query_objlist() (src/pickup.c).

Now
  1. Interop: ClientCallback_SelectMenu returns three int64 values per row,
     [identifier, count, itemflags], and lib_select_menu
     (win/win32/xpl/libshare/libproc.c) copies all three. It cancels the menu
     when the returned size is below three values per row.
  2. The flag is relative to the menu's default:
     MENU_ITEMFLAGS_STASH_TOGGLED means "this row takes the opposite of the
     stash default". Every window port's select_menu() sets itemflags; ports
     without stash marks set MENU_ITEMFLAGS_NONE, which means "the default",
     so they keep their behavior in Pick up (default off) and Pick & Stash
     (default on) without knowing start_menu_ex()'s mflags. An absolute flag
     was rejected because every port would then have to apply the default.
  3. query_objlist() turns STASH_TOGGLED and the default (STASH_BY_DEFAULT)
     into the absolute MENU_ITEMFLAGS_STASH that pickup() and menu_loot()
     read. The count is plain again; -1 (all) and -2 (long tap) keep their
     meanings. MENU_COUNT_STASH_TOGGLED_BASE and MenuCountStashToggledBase are
     gone.
  4. Ports that set itemflags: libshare, tty (win/tty/wintty.c), curses
     (win/curses/cursdial.c), Win32 (win/win32/mhmenu.c), X11
     (win/X11/winmenu.c), Qt (win/Qt/qt_win.cpp), Qt4 (win/Qt4/qt4menu.cpp),
     GEM (win/gem/wingem.c), GNOME (win/gnome/gnmenu.c), Amiga
     (sys/amiga/winmenu.c, which also now allocates with sizeof(menu_item)),
     Mac (sys/mac/macwin.c), Windows CE (sys/wince/mhmenu.c) and the old
     Android port (sys/android/winandroid.c). hup, dump and safe select_menu
     return no items.

Why replays are not affected
  - The recorder (GHGame.cs) writes a long[] argument as its length followed
    by its values, and a null array as length 0. The SelectMenu record is
    RecordFunctionCall(SelectMenu, winid, how, picklist, listsize, cnt); only
    the array's length and listsize (cnt * 3) change.
  - The only replay player (GHApp.cs, case RecordedFunctionID.SelectMenu)
    reads the array length, skips that many values, reads listsize and count,
    and uses only winid, how and count. Old and new apps run the same code, so
    replays play across the change in both directions.
  - GHReplayFiles scans for the GUI_CMD_LOAD_GLYPHS signature and does not
    walk records by size. No test and no server code parses replay contents.
  - ReplayVersionCompatibility (GHConstants.cs) is therefore unchanged.

What it does change
  - The C# and C sides of select_menu: the GUI and its engine library must
    come from the same build, as they always do.
  - Saves are not affected: menu_item is never saved.

Verify
  - Every window port's select_menu() sets itemflags (search for allocations
    of menu_item / MENU_ITEM_P).
  - Pick up and Pick & Stash in tty: nothing stashed / everything stashed.
  - A replay recorded before the change plays in the new version, and one
    recorded after it plays in the previous version, past a Pick up menu.
